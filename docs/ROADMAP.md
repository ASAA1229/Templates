# Roadmap

Roadmap sequencing is provisional. The exact MVP boundary and dependencies must be approved before implementation. Every phase remains subject to the ₹0 operating-cost constraint.

## Phase 0 — Repository and product foundation
- [x] Initialize private repository and taxonomy placeholders.
- [x] Document product vision and target architecture direction.
- [x] Create POC and initial user-story backlog.
- [x] Document main/dev/new/fix/test branch strategy and create branches.
- [ ] Review and approve POC, stories and MVP boundary.
- [ ] Complete architecture decision records (ADRs).

## Phase 1 — Implementation blueprint
- [ ] Define exact MVP modules, features and exclusions.
- [ ] Select frontend, backend, database, storage and API technologies.
- [ ] Produce context/container/component/deployment diagrams.
- [ ] Finalize ERDs, schemas, migrations and API contracts.
- [ ] Create screen inventory, routes, wireframes and component specifications.
- [ ] Select CI/CD, build, test, security and observability tools.
- [ ] Define detailed test cases, quality gates and release criteria.
- [ ] Break work into dependency-ordered development tasks.

## Phase 2 — Owner-first MVP foundation
- [ ] Secure owner authentication, sessions and recovery.
- [ ] Unified workspace, navigation and basic dashboard.
- [ ] Project and requirements management.
- [ ] Catalog metadata and validated initial template/asset structure.
- [ ] Owner administration, audit and configuration foundations.

## Phase 3 — Project initialization and engineering workflow
- [ ] Initialize project from template or scratch.
- [ ] Import/connect source repositories.
- [ ] Reproducible development and build workflow.
- [ ] Automated unit/integration testing and evidence reporting.
- [ ] Requirement-to-task/code/test traceability.
- [ ] Project documentation and lifecycle status.

## Phase 4 — Quality, DevOps and release
- [ ] CI pipeline and quality gates.
- [ ] Security, dependency and license checks.
- [ ] Environment configuration and secrets management.
- [ ] Packaging, artifact integrity and release workflow.
- [ ] Local deployment, smoke tests and rollback.
- [ ] Monitoring, backup and restore verification.

## Phase 5 — Reuse, collaboration and optional AI
- [ ] Template versioning, compatibility and safe updates.
- [ ] Reusable component and design-system library.
- [ ] Team roles and collaboration.
- [ ] Optional JARVIS integration for approved chatbot, agents, monitoring and model orchestration.
- [ ] Advanced AI governance and agent evaluation.

## Phase 6 — Business ecosystem and productization
- [ ] CRM, sales, proposals, quotations and contracts.
- [ ] Finance, accounting, HR, payroll and procurement.
- [ ] Support, service management, knowledge and business automation.
- [ ] BI, risk, compliance and continuity.
- [ ] Multi-organization tenancy and organization customization.
- [ ] External-company offering and licensing only after security, operational and commercial approval.

Do not advance a phase merely because its code builds. Require acceptance criteria, test evidence, security review, documentation and owner approval.
